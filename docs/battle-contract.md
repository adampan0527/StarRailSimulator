# 战斗输入契约 v1

[JSON Schema](../contracts/battle-session.v1.schema.json) 与 [共享样例](../contracts/battle-session.v1.example.json) 是 M02 战斗核心与 M03 档案应用层的共同接口。运行 `npm test` 可验证样例结构和引用。样例中的 `fixture.*` 版本、关卡和装备是合成数据；样例范围和验收记录见 [M01 离线基线](m01-baseline.md)。

- **身份和归属。** `character_form_id` 是注册表分配的稳定 ID，例如 `march_7th.preservation`。它不因本地化或显示名变更而改变，机制独立的形态拥有不同的 ID。队伍持久化只保存角色形态 ID；会话用 `unit_id` 区分场上单位。`unit_id` 在会话全局唯一，敌方即使同种也使用不同实例 ID。`team` 的顺序为编队站位，`waves` 外层是波次，内层按现场从左到右排序。
- **冻结输入。** M03 在开战时解析全局档案和当前配装，把配置逐值拷入 `input.team[*].config`，保存等级、突破、星魂、行迹技能等级和已激活行迹、光锥及叠影、六个遗器槽。`null` 明确表示空位。遗器主词条数值由锁定的数据版本按等级求得，副词条整数用百万分之一原单位表示（速度 2.3 → `2300000`，暴击率 2.9% → `29000`，百分比以 1 表示 100%）。装备快照无需查用户档案或库存。`starting_energy_milli` 以千分之一能量为单位。初始生命为满值，韧性、回合与关卡效果由关卡和版本定义，v1 不支持战斗中途接档或秘技开场。
- **版本独立。** `schema_version` 表示交换格式；`game_version` 标识适用的游戏版本，纯合成样例用 `0.0` 占位；`rules_version`、`data_version`、`rng_version` 分别指定规则、只读数据和随机算法。`seed` 是调用方提供给模拟器的无符号 32 位整数。缺少兼容版本应报错，不能默用最新版。展示名与规则资源由版本化数据查找，不属于输入。
- **合法指令。** 核心在当前决策点生成可用的 `basic`、`skill` 或 `ultimate` 及对应目标。指令带 `decision_index`（从 0 起，每次被接受后递增）、`actor_id`、`action` 和 `target_id`。选择目标时传实例 ID；无需玩家选目标的技能传 `null`。M02 在语法校验之后还须校验规则版本、数据引用、目标阵营及状态、资源和施放时机；过期或非法的指令不改变状态。敌方或自动触发的动作由核心结算，不写入玩家指令表。
- **两端如何使用。** M03 的合成夹具适配器输出 `input` 和空的 `commands`。M02 载入 `input`，把 `commands` 作为已接受指令按序回放。样例含部分已接受指令。两端的集成测试读取同一份 JSON。真实角色的强化状态和奇缘星魂保存在独立的 [M03 队伍快照](m03-profiles.md)。新增规则所需的兼容变更应同时更新两个调用方与样例。

M02 的合成数据覆盖、结算顺序和 v1 决策窗口见[离线战斗核心](m02-core.md)。
