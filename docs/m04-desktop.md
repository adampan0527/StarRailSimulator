# M04 · 桌面训练与回放

## 使用流程

1. 启动 Windows 桌面应用，在「组队」创建命名配队。点击四个站位从角色库选人，保存后可在「已保存配队」切换。角色属性读取角色库中的当前档案。
2. 在「组队」选择战场。选择「自选敌方（4.7.0）」时，为各站位挑选怪物并分别设置等级。生命、防御、速度和弱点自动显示。选择「合成训练」时，首次进入会创建四个合成角色的站位和初始配装。从上方选择靶机，调整并保存站位后可开战。「训练配装」支持装备或卸下训练装备、调整训练靴速度词条，以及保存和切换命名方案。保持初始四人、站位、装备和双目标时，可复现 [M02 的完整战斗](m02-core.md#固定夹具的独立预期)。
3. 战斗页列出当前行动者、按当前行动条排序的单位和资源。选择普攻、战技或已充能的终结技，根据需要选择目标，再执行指令。
4. 每条已接受指令自动保存。打开「历史回放」，选择一场训练并用「定位事件」查看普攻、击破、终结技和结算等事件。未结束的战斗可以继续执行指令。
5. 将开拓者训练靴的速度副词条从 `+2.3` 改为 `+2.6`，保存并新开一场同阵容战斗。两场在各执行前两条基准指令后，开拓者的首次行动分别为 `108.342362 AV` 与 `107.991361 AV`。

训练使用随程序提供的 M02 合成数据。正式服角色档案和库存使用单独的存档。在构建 Release 前按 [M03 导入流程](m03-profiles.md#数据来源与离线重建)生成 `catalog.json`，构建出的可执行文件会内置正式服目录。已有手动导入的目录优先使用。缺少内置数据的构建仍可在「角色」或「遗器」页手动导入。到「遗器」录入库存，在「角色」搜索并打开角色卡片，设置星魂和穿戴遗器，再回到「组队」选择角色。相同数值的两件遗器独立入库，每件遗器至多有一名穿戴者。已穿戴的遗器可修改同部位的配置，卸下后可删除或改部位。正式服开战和计算等待关卡与角色战斗效果接入。

## 组队与敌方阵容

- 「组队」是配置和开战的入口。从战斗或训练配装返回时保留当前战场、已选目标和未保存的站位。未结束的训练可通过「继续战斗」或「历史回放」恢复。
- 自选敌方显示五个固定站位卡片。点击空位选敌，点击已选卡片可更换怪物。移除会清空该站位，其他敌人保留原位。各站位可重复选同种怪物并分别设置 1–100 级。空位选敌默认 80 级，换敌沿用当前站位的等级。
- 从 2,781 条 `MonsterConfig` 源记录生成 383 张可选卡片。按规范化后的简中名称归并同名难度档，优先采用有图鉴标记的模板、模板本体和标准修正。来源 ID 仍可搜索到对应卡片。选敌弹窗支持普通／精英／首领筛选。[预览数据](../src/team/enemy-preview.json) · [4.7.0 源修订](https://github.com/DimbreathBot/TurnBasedGameData/commit/dad9155eb00fdeda31fb8456507c53590d49071f)
- 独立出场以关卡波次、无限波次编组和图鉴为证据。有关联的召唤者时，需有至少一处未与召唤者同组的出场。银枝的「盾」「授勋」及「枪尖」按游戏的 `Argenti_Totem` 标签排除，涵盖刷怪池预先登记雕像的情形。召唤脚本中的动态出场尚未全量复核。[筛选规则](../scripts/m03/selectable-enemies.mjs) · [回归用例](../tests/enemy-preview.test.mjs)
- 生命、防御和速度由模板、变体倍率、精英组和等级曲线在导入时计算。7 种可选怪物缺少可确认的速度，对应数值显示为「—」。预览使用怪物自带的分组。正式关卡的附加修正和技能行为尚未接入。

## 接口和存档

- Tauri 命令在后台调用应用层，前端显示 Rust 核心返回的合法指令、行动顺序和单位状态。行动列表与战斗调度共用排序规则。行动顺序随当前行动条和后续指令重新计算。
- %LOCALAPPDATA% 下应用标识目录的 `training` 子目录存放 `training-profiles.sqlite` 和 `training-replays.sqlite`。配装沿用 M03 档案接口。开战时把档案冻结为战斗会话 v1，独立保存完整初始条件、版本与种子。
- `characters` 子目录保存手动导入的正式服数据包和 `profiles.sqlite`。档案 schema v2 增加遗器实例和一对一穿戴关系，v3 增加持有光锥实例及独占的装备关系。v1 和 v2 存档就地迁移，预设已有的光锥继续作为自定义光锥。四站位使用存档已有的站位字段，保存星魂、光锥和遗器穿戴在同一事务内完成。冻结配置时读取所装备的库存实例数值。
- 回放存储使用 SQLite schema v1。接受指令和更新会话在同一事务内完成。打开回放时按原有快照和指令重算，版本不兼容时显示提示。修改配装不会改写已开始的会话。
- `character_index` 返回命名配队列表，`character_save_team` 按稳定 ID 更新或创建配队。配队复用现有 `teams` 和 `team_members` 表；之前保存的 `desktop.team` 直接出现在列表中。新角色默认档案与站位在同一事务写入。

## 合成数据计算

- DPR 使用独立的固定靶场，取前 3 个关卡轮次 `[0, 350 AV)` 的全部伤害。内置测试角色可计算全队与个人贡献及逐靶机命中明细。主配队入口按已保存队伍检查可计算性，正式服角色的战斗效果待接入。[场景与归因约定](m05-dpr.md)
- 最少行动值搜索从战斗核心枚举各决策点的合法指令，按当前行动值推进，直至确认所有敌人均被击败。返回通关指令及行动值；超过 20,000 条指令预算时注明本次预算的结果。存在随机分支时提示选择确定性战场。合成计算在后台使用冻结的配装和目标，只有手动开战会创建历史记录。
- 独立穷举与回放核对首批最优解 `108.342362 AV`；另有双波次和预算用尽测试。单角色夹具核对首轮有效伤害 525、三轮有效伤害 1,000 及固定分母。[规则测试](../crates/battle-core/tests/analysis.rs) · [桌面应用层测试](../src-tauri/src/workbench_tests.rs)
- Edge 模拟 IPC 使用 4.7.0 角色目录验证 94 个角色可选，检查键盘弹窗、重复上阵禁用、保存失败重试、两队切换与重载、返回主页刷新属性，以及合成计算入口的状态和结果。360、704 和 1056 CSS px 下四站位同排，页面无横向溢出。真实档案的写入和重开由 Rust 回归测试覆盖。[存档测试](../src-tauri/src/character_archive_tests.rs)
