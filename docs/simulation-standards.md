# 模拟与游戏数据规范

适用于战斗引擎、角色与装备机制、游戏版本数据、回放和优化器。通用约定见 [代码规范](coding-standards.md)。

## 规则、数值与顺序

- 手动战斗、自动策略、回放与优化器共用一套规则实现。战斗核心接收当前状态和合法指令，按规则推进至下一决策点；非法指令返回可识别的错误，不产生部分结算。
- 通用规则集中维护，例如行动推进、伤害公式、韧性、状态到期和触发优先级。单个角色、敌人或装备特例放在对应机制模块，通过统一的触发点接入。用现有规则组合能表达的效果留在数据层；遇到真正的新行为，先用可复现案例写清它的触发条件与效果，再扩展代码。无需为假设中的机制提前建通用脚本引擎。
- 显式定义结算阶段，以及同一时点多个事件、终结技插入和追击的排序依据。规则排序不依赖哈希容器迭代顺序、运行线程或系统时间。游戏里的真实顺序无法确认时，记录当前假设及验证状态。
- 明确百分比的内部尺度、行动值的精度、舍入和上下限，并区分游戏显示值与计算值。不要把面板四舍五入的速度用于行动调度。影响战斗的近似应集中定义，避免不同模块各自舍入或添加容差。

## 数据与游戏版本

- 角色形态、技能、装备和敌人用稳定 ID；名称用于显示和本地化。数据导入时验证 ID 唯一性、跨表引用、单位、数值范围和必填字段。缺失或不支持的效果显式标记，不用零值或空实现默默补齐。
- 静态游戏数据按快照管理，记录目标游戏版本、来源及其修订、导入方式和可验证的出处。优先用可重复执行的导入过程。支持手工校正时，把修正与原始数据区分开并说明证据。
- 区分游戏规则版本、数据快照和存档格式版本。修改某个版本的规则含义时，保留或明确标记受影响的旧回放；不能用新规则重算后当作原结果。画面和日志中的「已验证」「近似」「未支持」应能对应到实际覆盖状态。

## 回放与随机性

- 开战和启动搜索时冻结有效配置：全局角色档案解析后的配装、队伍、敌人、起始条件、规则与数据版本。回放保留重放所需的快照或稳定引用，同时记录指令序列与随机种子；若要跨引擎升级重放，还需有兼容的规则与随机算法版本。缺少兼容实现时应说明无法重算。
- 通过会话显式提供随机源。给定可兼容的版本、初始输入、随机种子和指令序列，战斗事件的顺序与结果应一致。并行评估的样本种子来自稳定的样本编号，不由工作线程领任务的先后决定；固定评估预算应支持稳定地比较结果。
- 战斗日志记录可追踪的事件，至少能指出触发来源、作用目标和发生时点。批量模拟可以关闭明细日志与逐事件分配；关闭日志不得改变结算结果或随机序列。

## 优化与性能

- 每项搜索记录目标、战场、轮次口径、预算与证据。全队 DPR 对比使用相同的关卡轮次窗口和同一套伤害口径；展示必要的副指标（例如通关耗用行动值）。真实库存模式按装备实例校验独占与锁定限制，理论配装单独标识。
- 先用小规模穷举结果验证搜索；启发式搜索标为「本次预算内找到的最佳」，仅在给定模型和搜索范围内有证明时标为最优。策略只能使用已观察到的信息。随机场景用同一批样本比较候选，必要时用额外样本确认领先方案。
- 长时间搜索使用后台有界执行队列，支持取消、控制并行度和批量发送进度。候选评估不逐次访问数据库，不为每一步生成 UI 数据。结果按明确规则排序并处理同分。
- 性能改动先用 Release 下的代表性场景找瓶颈，再用同一输入对比修改前后的用时与内存。记录机器、线程数、样本量和规则版本；同时验证结果一致，或说明经过验证的精度取舍。

## 新增或修改机制时

1. 记录适用规则版本、数据来源和仍不确定的行为。M02 以公开规则和离线合成夹具为依据，不绑定客户端版本或游戏关卡。
2. 把数据、通用规则和专属特例分别放到负责它们的位置。对结算时机写清前置状态、触发条件、效果和到期时点。
3. 用最小合成夹具覆盖触发和不应触发的情形；涉及行动顺序、击破、叠层或击杀边界时，再加一条相应的交互用例。期望值独立计算，避免用被测实现生成答案。
4. 对影响整场结果的改动加一份固定输入的回放夹具。优先断言关键事件和数值，例如谁先行动、能量何时扣除、击破何时生效；更新期望结果时说明原因，不直接接受整份快照差异。
