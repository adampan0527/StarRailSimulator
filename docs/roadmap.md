# 开发路线图

> 阅读入口：[开发路线图 HTML 汇报](../html_report/01_开发路线图/index.html)。本文件是维护源；更新后按 [汇报维护说明](../html_report/README.md) 重新生成。

目标：交付一款可离线安装和运行的 Windows 战斗模拟器。首发围绕一个明确的游戏版本及已验证的角色、装备和敌人展开，支持全局角色档案、手动战斗、回放、打法搜索和全队 DPR 配装优化。未验证的角色或机制明确标出；全角色、全模式和账号导入另行立项。

状态使用「未开始 → 进行中 → 待验收 → 已验收」，遇到阻碍标为「阻塞」并记录原因与解除条件。完成实现后先标「待验收」；全部验收项通过并附证据后才标「已验收」。验收记录填写日期、构建或提交标识、证据位置和仍适用的限制。可直接链接测试、回放、截图、基准报告或安装记录。若改动导致已验收项失效，将其重新打开并记录原因；若拆分或调整里程碑，保留原编号并记录新编号、依赖变化及理由。

每个里程碑可包含多个实现任务。开工时按可独立验证的改动拆分，记录验证命令；阶段切换前保留上一版通过验收的构建、数据与夹具。存档格式或规则数据有变更时，单独验证恢复路径，避免通过回退程序版本覆盖用户档案。

## 里程碑与验收

所有阶段遵循 [代码规范](coding-standards.md)；规则、回放和搜索遵循 [模拟与游戏数据规范](simulation-standards.md)；用户可见界面遵循 [前端设计规范](design.md)。尚未安装依赖、接入 CI 或执行验证时如实记录。

### M01 · Windows 骨架与验收基线

用 Rust + Tauri 建立最小 Windows x64 应用。锁定工具链与依赖，搭好本地检查与测试入口。定义角色形态 ID 和战斗输入边界，用合成夹具验证契约。记录首发支持的 Windows 版本、参考机器、性能样本规模与计时口径。M01 仅验收离线工程底座。

- [x] 在干净开发检出中按文档安装依赖，完成 Windows x64 构建，并启动窗口执行一次前端到 Rust 的调用。
- [x] 格式、lint、类型检查与已有测试可按文档运行。未接版本库或 CI 时保留本地执行记录；接入后让 Windows CI 执行相同检查。
- [x] 交付并验证带最小样例的共享契约，写清角色形态 ID、配置快照、合法指令、规则与数据版本字段。M02 和 M03 分别在接入时使用同一份样例；修改契约时同步更新两个调用方。
- [x] 固定包含四个角色形态和至少两个可区分敌方目标的离线合成样例。登记 M05–M07 使用的参考机器、样本定义和计时口径，并记录 M07 的验收阈值。

**验收证据：** 构建与启动记录、锁文件、共享契约、四人双目标合成样例及其校验值、基准约定。

### M02 · 可离线验证的 Rust 战斗核心

用固定的合成输入在不加载桌面界面的情况下跑完一场模拟战斗。首批覆盖行动值、拉条、能量、战技点、终结技插入、伤害、增减益和弱点击破，以及合成敌人的行为。公开资料用于建立规则模型，验收以锁定的合成规则与数据为准。

- [x] 用固定的合成夹具跑完一场模拟战斗。以独立计算的预期值检查关键行动顺序、技能目标、战技点、能量、状态与击破时点；伤害按事先写明的数值精度和舍入规则核对。
- [x] 相同版本、初始条件、指令与种子产生相同事件顺序和结果；关闭详细日志时结果一致；非法指令不会留下部分结算。
- [x] 用 Release 构建跑首组基准，记录每秒完整模拟场次、单场耗时、线程数与峰值内存，作为后续比较基线。

**验收证据：** [完整合成夹具与手算结果](m02-core.md)、[规则回归测试](../crates/battle-core/tests/session.rs)、[Release 原始测量](m02-benchmark.json)。

### M03 · 可保存和复用的全局角色档案

实现本地持久化。每个角色形态有一份全局档案，记录等级、行迹、星魂、光锥叠影和六件遗器，可管理多套配装和当前方案。队伍只引用角色形态 ID。4.7.0 正式服数据支持角色及光锥默认 80 级，光锥叠影 1–5 独立查询。

- [x] 关闭并重新打开本地档案后，角色配置、预设和队伍引用一致。用应用层测试验证：编辑两个队伍共用角色的当前配装后，两队重新生成的模拟输入均读取新配置，已生成的输入快照保持原值。此项不依赖战斗核心或图形界面。
- [x] 无效装备槽位或非法配置无法保存；保存失败不会留下部分写入，未保存内容可重试。
- [x] 以固定修订逐 ID 核对 4.7.0 正式服角色、光锥和遗器，验证角色技能与属性成长、星魂、六槽规则及光锥五档叠影。角色强化状态和奇缘星魂可随配装冻结。

**验收证据：** [覆盖对账](m03-coverage.json)、两队引用同一角色的集成测试、重启及保存失败演示。

#### 进展记录

- 2026-11-16：锁定 4.7.0 两个源修订，实现离线导入、SQLite 档案、版本化队伍快照和 M02 合成契约接入。[实施与验证记录](m03-profiles.md)
- 2026-11-16：完成 94 个角色形态、172 张光锥及 790 条遗器记录的离线对账。两个 Windows 进程验证重启、共享配装与旧快照。事务回滚及原草稿重试通过。Rust 工作区 15 项测试与 npm 检查通过，M03 验收通过。[验证证据](m03-profiles.md)

### M04 · 从配装到战斗回放的桌面原型

把档案与核心接入桌面应用。用户可以编辑配置、组队、选敌、逐回合操作、查看结果和回放。

- [x] 新用户无需修改文件，即可保存配装、选择目标、使用普攻和战技、插入终结技并完成 M02 的合成战斗。界面显示行动顺序、生命、韧性、能量和战技点。
- [x] 重启应用后能打开旧回放并定位关键事件；切换星魂或速度遗器后，以新会话展示可预期的差异，旧回放结果不变。
- [x] 从正式服「遗器」页录入库存，在「角色」保存星魂和穿戴，再从「组队」点击四个固定站位选择角色。属性和命途可组合筛选，保存并重启后空位与穿戴状态一致。
- [x] 使用已生成数据构建 Windows Release 后，空存档首次进入「角色」即可加载内置的正式服目录，无需手动导入。
- [x] 角色页可组合筛选遗器部位、套装、主词条和副词条。光锥弹窗的自选与光锥库标签均可按命途筛选，保存后重开保留光锥实例与叠影。
- [x] 角色页使用遗器图标卡片选择穿戴。四组筛选支持弹窗多选，打开时默认筛选所点槽位。当前穿戴和其他角色已穿戴的实例有状态标记，应用筛选后可继续选择遗器。
- [x] 「穿戴遗器」直接展示已装备遗器的本地图标、强化等级、主词条、副词条数值和可用的副词条强化次数。卡片和空位均可打开对应部位的选择弹窗。
- [x] 光锥录入、库存与装备选择展示本地图片、星星、命途和名称。五星使用金色卡片，四星使用紫色卡片，三星使用蓝色卡片。
- [x] 光锥录入、库存和装备选择按首次上线版本倒序，同版本按星级降序，同星级按上线批次倒序，同批按英文名 A–Z。
- [x] 「角色」页卡片展示头像、名称、属性图标和命途图标，可组合使用名称搜索、属性筛选和命途筛选。角色列表和组队选人与光锥列表采用相同排序。打开卡片可查看对应形态的立绘并配置角色，返回后恢复筛选和卡片位置。
- [x] 主页从全局角色库选人并读取当前配装面板，可创建、命名、保存和切换多套配队，原已保存配队可继续使用。
- [x] 从「组队」按名称、怪物 ID 或类别查找 4.7.0 可独立出场的敌人，逐站位设置等级并查看只读属性。同一入口能启动合成战斗，返回后保留已选目标。
- [x] 自选敌方提供五个可留空的固定站位。敌方卡片显示头像、名称、弱点及生命值、防御力和速度。宽窗口五个站位同排，窄窗口自动换行。
- [x] 使用 4.7 正式服账号和本机导出器，从「遗器导出」接收已穿戴与未穿戴遗器，复制文件链接并核对导出的库存和词条精度。
- [x] 从「遗器」页导入已保存的 JSON，显示实际库存。重复导入同一份快照不会重复新增实例。
- [x] 遗器导入保留游戏穿戴、词条强化次数和未解锁词条预览。已有库存可通过重新导入补齐信息，预览词条解锁前不计入属性。
- [ ] 使用 4.7 正式服账号，从「账号导入」打开 Archiver 并接收完整快照，核对角色养成、光锥、遗器、穿戴关系和附加账号字段。
- [x] 遗器卡片在副词条名称前展示离线图标，在数值右侧用彩色数字圆标展示已记录的 0–5 次强化。
- [x] 遗器卡片副词条单行排列，数值最多显示三位小数，相邻强化圆标之间留有间距。
- [x] 「遗器」页只展示五星遗器，每件一张带本地图标的卡片。卡片隐藏实例编号，可点击打开对应的编辑表单。
- [x] 五星遗器卡片展示副词条数值，库存支持翻页和跳页。主词条、副词条、套装与部位均可多选，四组取交集，副词条匹配门槛最多为已选项数。
- [x] 「遗器」页的四种筛选各有多选弹窗，主词条、副词条和套装选项有离线图标，部位可按外圈、内圈整组或按单个部位勾选。主词条和副词条按固定优先级排列。
- [x] 「遗器」页套装筛选按首次上线版本倒序。同版本按套装 ID 升序。结果卡片先按强化等级降序，同等级沿用套装筛选顺序，排序覆盖所有页。
- [ ] 按 `design.md` 审查配装页与战斗页；在 100% 和 150% Windows 显示缩放下检查布局、字体和关键路径，键盘可操作，加载、空白和失败状态可理解。

### M06 · 有库存约束的全队配装优化

用户可以在界面录入和管理本地库存，为实际装备分配稳定实例 ID，并锁定需要保留的分配。给定队伍、真实库存和锁定项，联合分配配装并对入围组合重新搜索打法。比较全队 DPR 与原方案，附上装备变化和关键行动差异。

- [ ] 从界面录入一件未装备遗器并保存，重启后库存和锁定状态仍在；通过界面完成库存录入、搜索、预览和应用，候选可以使用未装备物品。
- [ ] 在小库存夹具中，和独立穷举的配装与打法组合比较，精确模式得到相同的最优分数；所有候选都符合槽位、锁定和物品独占约束。至少一个夹具体现速度配装改变行动顺序或增益覆盖，从而改变全队结果。
- [ ] 原方案和候选按同一关卡轮次窗口、伤害口径、随机样本和可比打法预算评估；显示 DPR、差值及需要的通关指标。
- [ ] 搜索、预览和取消均不改全局档案；用户应用时整套方案一次保存。搜索期间全局档案或库存已变更时重新校验，冲突有明确提示。

**验收证据：** 库存到应用的操作录屏、小库存穷举对照、速度变动回放、装备约束与应用事务测试。
